# FORK-DELTA — VibeDev on DeepSeek Harness

This repository is VibeDev's fork of [deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness) (MIT).
`main` is an upstream release tag plus the VibeDev changes recorded here. The plan behind it lives outside the repo in
`C:\vdp-tools\coordination\DSH-FORK-PLAN-1002.md`.

- **Upstream base:** `dsh-v0.2.1-alpha.2`, merged over `dsh-v0.2.1-alpha.1` on 2026-10-10 (see Merges below).
  Remote `upstream` tracks deepseek-ai/deepseek-harness.
- **Keep upstream identities that plugins depend on:** the `@deepseek-ai/*` package names, the runtime version, `DSH_*`
  variables, bundle row ids, the session format, and project-local `.dsh/` directories.
- **Put VibeDev features in new packages** under `packages/vibedev/*`: `@vibedev/*` packages packed into the app with the
  dsh release family and never published to npm. They carry the dsh family version (`0.2.1-alpha.2` now), so an upstream merge
  that moves the root version must move theirs too, or `release:pack` refuses the family.
- **Override upstream bundle rows from our bundles.** Never edit `packages/bundle/*/cordis.patch.yml`; upstream adds rows to
  them in almost every release.
- **Every change to an upstream file gets a row below,** so each upstream merge can re-check it.
- **`.github/workflows/*` and their tests follow upstream.** Dependency bumps that land on the fork (dependabot) are dropped
  for upstream's pinned versions at each merge; the fork keeps no workflow changes of its own.

## Built-in external plugin

The local verification build pins `@vibedev-si/dsh-vibedev` 0.3.0 in both the CLI anchor and defaults bundle, using the same immutable Git commit archive with lockfile integrity. Production defaults to `https://api.vibedev.studio` with development keys disabled; the candidate overlay is removed. The component owns canonical-origin credentials and task namespaces, app-token PKCE login, selected-API search and media control requests, and verbatim signed storage URLs. Historical unmarked state stays intact but is not imported, restored or resubmitted. Other accounts and local data remain untouched; there is no generation failover across origins. The archive is bundled into the installer without requiring an npm publication; the build does not remove the server's 503 gate.

The identical archive is checked in under `apps/desktop/resources/bundled-account`. Package-set preparation verifies its identity, version and SHA-512 against the immutable CLI dependency and repository lockfile, then adds it to the existing local package closure and file overrides. This preserves pnpm's `blockExoticSubdeps` policy: the installed runtime resolves the component from a verified local tarball rather than an exotic transitive URL. A missing or mismatched archive stops packaging before runtime installation.

Login diagnostics (2026-10-09): the component retains an authoritative attempt through listener preparation, browser authorization, credential exchange, atomic local commit and terminal outcome. The desktop welcome flow projects those states without altering the official DeepSeek account contract. Failures show localized network, timeout, gateway rejection/unavailability, protocol, storage or callback guidance and optional allowlisted support details. Logs never contain authorization codes, PKCE verifiers, grants, callback URLs, response bodies or raw error messages. Cancel and expiry abort exchanges and fence late responses; the atomic credential write finishes before sign-out removes the grant.
